The Background Story

The Missing Half of Cloud Reverse Proxying

On your Ubuntu VPS (103.174.102.116), hosting multiple applications behind Caddy is effortless. We built caddy-cli to inspect routes and programmatically manipulate /etc/caddy/caddy.json with zero downtime.

But Caddy is only the front door. Caddy receives HTTPS traffic on ports 80/443 and dials an internal upstream like localhost:3000. If no application is running on port 3000, Caddy will return a 502 Bad Gateway.

Who ensures your Node.js application boots up when the server restarts? Who restarts it in 5 seconds if an uncaught exception crashes it? Native Ubuntu Systemd (/etc/systemd/system/).

The KeshavSoft 1-to-1 Mapping Convention

To prevent confusing multi-app process managers, every subdomain on the VPS maps 1-to-1 to a dedicated systemd service unit:
appointment.keshavsoft.com → /etc/systemd/system/appointment.keshavsoft.com.service → /root/KeshavSoft/appointment-notifier (Port 3000)

The Problem: When you manage 6 to 10+ subdomains, returning months later creates cognitive load: Which services exist? Which internal ports are taken? If I have a list of subdomains, which ones are missing systemd units?

The Solution: ubuntu-service-cli gives you instant tabular inspection, array-based subdomain checking, port discovery, and unit generation in under 1 second.

VPS End-to-End Architecture

How the Two Halves Fit Together

1. Front-Door Gateway caddy-cli

Caddy Reverse Proxy

  • • Listens on :80 / :443
  • • Automatic TLS & HTTPS certificates
  • • Dial target: localhost:3000
  • • Config: /etc/caddy/caddy.json
  • • Tool: npx caddy-cli add proxy ...
2. Backend Engine ubuntu-service-cli

Native Ubuntu Systemd

  • • Listens on localhost:3000
  • • Auto-boots on VPS reboot (systemctl enable)
  • • Revives in 5s on crash (Restart=on-failure)
  • • Units: /etc/systemd/system/*.service
  • • Tool: npx ubuntu-service-cli check ...

        Programmatic JavaScript API
      

      
Embed Directly in Node.js Scripts

      

        Import ubuntu-service-cli in your deployment pipelines or custom healthcheck scripts:
      


      

        
import { checkServices, listServices, findServiceByDomain } from "ubuntu-service-cli";

// 1. Check an array of domain strings:
const check = checkServices([
    "appointment.keshavsoft.com",
    "lab14.keshavsoft.com",
    "newapp.keshavsoft.com"
]);

console.log(check.presentCount); // 2
console.log(check.missingCount); // 1
console.log(check.missing[0].domain); // "newapp.keshavsoft.com"

// 2. Inspect a specific service:
const svc = findServiceByDomain("appointment.keshavsoft.com");
console.log(svc.port);             // "3000"
console.log(svc.workingDirectory); // "/root/KeshavSoft/appointment-notifier"
console.log(svc.status);           // "active"
